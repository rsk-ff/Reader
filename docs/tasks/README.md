# Task documents

任务文件用于多回合开发和跨会话交接，不是让用户填写的工单。Codex 负责创建、更新和归档。

## When a task file is required

以下任一情况建立任务文件：

- 预计需要多个用户反馈或实现回合。
- 会调用 Pi。
- 涉及重要设计、多个模块或较高风险。
- 自动化验证后还要等待用户视觉/交互验收。
- 当前会话可能在完成前切换。

单回合即可完成的只读诊断、小修、打包或机械操作不必建立任务文件。

## Lifecycle

1. Codex 从 [`TEMPLATE.md`](TEMPLATE.md) 创建 `active/YYYY-MM-DD-short-name.md`。
2. 开始实现前写清目标、现状、范围、验收和基线。
3. 每次实现、发现、用户反馈和验证后更新相应章节。
4. 等待用户验收时把状态设为 `waiting_user_acceptance`，并保留准确检查清单。
5. 完成时记录结果和剩余风险，移动到 `archive/`，更新 `docs/STATUS.md` 和需要的其他文档。
6. 同一连贯目标在新会话中继续使用原活动文件；独立目标创建新文件。

## Rules

- 文件必须自包含：不了解旧会话的人只读仓库和任务文件就能继续。
- 记录事实、决定和证据，不粘贴完整构建日志、完整 diff 或代理推理。
- `Progress` 反映真实状态，不能把“代理声称完成”写成已验证。
- `Next action` 始终只有当前最具体的下一步。
- 用户不负责编辑、移动或清理任务文件。
